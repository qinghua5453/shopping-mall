# 04 实施计划

> 原则：每个阶段交付可运行、可测试、可部署的增量；不追求一次性写完，但每个阶段都必须有验收标准。
> 阶段之间不设时间估算，按依赖顺序推进。

---

## 1. 阶段总览

| 阶段 | 目标 | 核心产出 |
| --- | --- | --- |
| M0 | 工程骨架与基础设施 | 多模块工程、统一响应/异常、Flyway、Docker Compose、CI、ArchUnit |
| M1 | 会员与多端认证 | 注册、登录、短信、刷新、退出、多端会话、资料、地址 |
| M2 | 管理端权限 | 管理员登录、RBAC、权限缓存、菜单、审计日志 |
| M3 | 优惠券发放 | 券模板、发布/下线、领券中心、领券、我的券、券码生成/兑换 |
| M4 | 优惠券交易闭环 | 试算/选券、锁券/核销/释放、过期任务、退券、叠加规则、并发测试 |
| M5 | 生产加固与小程序的预留落地 | 可观测、限流、压测、安全、部署、小程序 Mock 联调 |

## 2. M0：工程骨架与基础设施

### 2.1 任务

1. 父 POM + 6 个模块：`mall-common`、`mall-security`、`mall-user`、`mall-coupon`、`mall-admin`、`mall-bootstrap`。
2. `mall-common`：
   - 统一响应 `ApiResponse<T>`、分页对象；
   - 错误码枚举、`BizException`、全局异常处理；
   - `TraceIdFilter`（MDC + 响应头）；
   - Jackson 配置：Long → String、时间格式、时区；
   - 参数校验分组、常用工具（雪花、脱敏、加密、Hash）；
   - MyBatis-Plus 基础配置（分页插件、乐观锁、自动填充、逻辑删除）。
3. `mall-bootstrap`：
   - 启动类、`application.yml` / `application-dev.yml` / `application-prod.yml`；
   - Flyway 接入与 `V*__create_*.sql`；
   - Actuator 健康检查；
   - ArchUnit 架构测试。
4. `deploy/`：
   - `docker-compose.yml`（MySQL、Redis、应用、Nginx）；
   - 应用 `Dockerfile`（多阶段构建）；
   - `.env.example`（不含真实密钥）。
5. CI：
   - `mvn verify`；
   - Flyway `validate`；
   - 镜像构建与 Trivy 扫描（可选）。

### 2.2 验收标准

- `./mvnw clean verify` 通过；
- `docker compose up` 后应用健康检查为 `UP`；
- 空库启动自动执行 Flyway，表结构完整；
- 任意接口返回统一响应结构并带 `traceId`；
- ArchUnit 能阻止跨层/跨模块非法依赖（构造一个反例验证）。

## 3. M1：会员与多端认证

### 3.1 任务

1. 手机号加密与哈希：`PhoneCipher`、`PhoneHasher`，密钥配置与轮换说明。
2. 注册：手机号 + 验证码 + 密码；唯一性校验；初始化会员号。
3. 登录：
   - 密码登录、短信登录；
   - BCrypt 校验、状态校验、失败计数与锁定；
   - 登录日志。
4. Token：
   - JWT 签发/解析、`aud` 区分 Realm；
   - Redis 会话、Refresh 轮换、重放检测；
   - 退出当前设备 / 全部设备 / 指定设备下线；
   - `token_version` 与改密失效。
5. 短信：
   - `SmsSender` 接口 + Mock 实现；
   - 验证码生成、存储、一次性校验、发送频率限制。
6. 会员资料、收货地址 CRUD、默认地址事务处理。
7. 限流：登录、短信接口。

### 3.2 验收标准

- 新用户可完成注册 → 登录 → 刷新 → 退出全流程；
- 同一账号在 PC 和 APP 同时在线，会话列表正确，可单独下线；
- 改密后所有旧 Token 立即失效；
- 同账号连续 5 次密码错误后被锁定；
- 短信验证码 60 秒内不可重复发送，验证成功后不可复用；
- 手机号在数据库中为密文，唯一索引基于哈希；
- 会员 Token 访问 `/api/v1/admin/**` 返回 `40109/403`；
- 登录、刷新接口有单元测试与 Testcontainers 集成测试。

## 4. M2：管理端权限

### 4.1 任务

1. 管理员认证：独立登录、刷新、退出、首次登录强制改密。
2. RBAC：
   - 管理员、角色、权限 CRUD；
   - 角色授权、管理员分配角色；
   - 权限树与菜单树；
   - 权限码与 `@PreAuthorize` 接入；
   - Redis 权限缓存 + 版本号失效。
3. 审计：
   - `@OperationLog` 注解 + AOP；
   - 记录操作人、路径、参数摘要、耗时、traceId；
   - 敏感字段脱敏。
4. 会员管理接口（列表、详情、启用/禁用）。
5. 初始化：`AdminInitializer` 从环境变量创建超级管理员；Flyway 写入权限种子。

### 4.2 验收标准

- 管理员登录后可获取权限码与菜单树；
- 无权限调用返回 403，前端菜单不显示；
- 修改角色权限后，相关管理员下一次请求即生效；
- `SUPER_ADMIN` 拥有全部权限且不可被删除；
- 所有管理端写操作产生操作日志；
- 管理员连续登录失败锁定生效；
- 密码泄露风险控制：数据库中无明文、日志中无密码/Token。

## 5. M3：优惠券发放

### 5.1 任务

1. 券模板：
   - 创建、编辑草稿、发布、下线；
   - 字段校验（类型、面额、门槛、有效期、库存、限领、折扣封顶）；
   - 发布后关键字段不可改。
2. 领券中心：
   - 已发布 + 领取窗口内 + 有库存；
   - 排序权重、分页、缓存；
   - 返回用户可领状态（已领/已领完/未开始）。
3. 领券：
   - 幂等键；
   - 限领校验；
   - Redis 预扣 + DB CAS；
   - 领取记录、券实例、使用流水初始化；
   - 失败补偿与日志。
4. 我的券：状态筛选、分页、角标数量、详情。
5. 券码：
   - 批量生成（同步/异步阈值）；
   - 券码分页、作废；
   - 兑换（登录、幂等、状态 CAS）。
6. 后台定向发券（会员 ID 列表，逐人幂等）。
7. 券模板与券中心缓存、缓存失效策略。

### 5.2 验收标准

- 后台可创建并发布满减/折扣/无门槛三类券；
- 券中心只展示可领取券，已领完/未开始状态正确；
- 同一 `Idempotency-Key` 重复领券只发一张；
- 每人限领生效；
- 库存 0 时拒绝领券；
- 券码可生成、导出、作废、兑换，重复兑换被拒；
- 我的券状态、有效期、数量正确；
- 领券接口 P99 达标（压测环境）。

## 6. M4：优惠券交易闭环

### 6.1 任务

1. 领域计算：
   - 适用范围匹配（全场/类目/SPU/SKU，含排除）；
   - 门槛按适用金额计算；
   - 满减、折扣、无门槛金额计算与舍入；
   - 叠加分组、规则表、组合枚举与上限。
2. 试算接口：可用/不可用原因、最优组合、用户指定券校验。
3. `CouponFacade`：
   - `preview`、`lock`、`confirm`、`release`、`returnOnRefund`；
   - 服务端重算，不信任客户端金额；
   - 多券锁定的事务与回滚；
   - 动作幂等（唯一键 + 状态 CAS）。
4. 状态机：
   - 未使用 → 锁定 → 已使用；
   - 锁定 → 释放；
   - 退款退券；
   - 冻结/解冻。
5. 定时任务：
   - 过期券处理；
   - 券库存对账；
   - ShedLock 防重复。
6. 并发与一致性测试：
   - 200 并发领 100 库存；
   - 同一券并发锁两个订单；
   - 重复核销/重复释放；
   - Redis 宕机降级。

### 6.2 验收标准

- 试算结果与实际核销金额一致；
- 不满足门槛/范围/叠加上限的券被正确拒绝且返回原因；
- 多券叠加符合规则表；
- 同一张券不能同时用于两个订单；
- 订单取消后券恢复为未使用；
- 支付后退款按模板策略退券/不退券；
- 过期券不可用且被任务正确置为过期；
- 并发测试断言：发放量 ≤ 库存，核销量 ≤ 1；
- 关键领域计算单元测试覆盖率 ≥ 80%。

## 7. M5：生产加固与小程序接入

### 7.1 任务

1. 可观测：
   - Micrometer 指标：HTTP、连接池、Redis、领券、登录、任务；
   - JSON 日志与敏感字段脱敏；
   - Prometheus 抓取与告警规则示例。
2. 安全：
   - 限流全覆盖（登录、短信、领券、兑换、试算）；
   - CORS 白名单、安全响应头；
   - 依赖漏洞扫描；
   - 越权与敏感信息测试。
3. 性能：
   - k6/JMeter 压测登录、领券、我的券、试算；
   - 根据结果确定线程模型（平台线程 / 虚拟线程）与连接池参数。
4. 部署：
   - 生产 Dockerfile、Compose/K8s 清单；
   - 环境变量与密钥清单；
   - 备份与恢复演练；
   - 优雅停机与健康探针。
5. 小程序：
   - `WeChatClient` 接口与 Mock；
   - `code2Session`、openid/unionid 绑定；
   - 手机号授权解密与绑定；
   - `MINI` 端登录联调。

### 7.2 验收标准

- 关键 SLO 在压测环境达标；
- 告警能触发并定位到接口与 traceId；
- 生产配置无明文密钥；
- 备份可恢复，RTO/RPO 符合目标；
- 小程序可完成登录、领券、查看我的券（Mock/沙箱环境）；
- 安全扫描无高危漏洞；
- 上线检查清单全部通过。

## 9. 完成定义（DoD）

每个功能合并前必须满足：

- [ ] 接口契约与 `03-api.md` 一致（路径、参数、错误码）；
- [ ] 数据库变更通过 Flyway 迁移，字段有注释与索引说明；
- [ ] 参数校验、权限校验、资源归属校验齐全；
- [ ] 写操作具备幂等或唯一约束兜底；
- [ ] 单元测试覆盖核心分支，集成测试覆盖主流程；
- [ ] 日志不含敏感信息，关键路径有指标；
- [ ] 异常返回统一错误码，不泄露堆栈；
- [ ] 文档（接口、表结构、配置）同步更新；
- [ ] 通过 ArchUnit 与 `mvn verify`；
- [ ] 代码评审通过。

## 11. 上线检查清单
